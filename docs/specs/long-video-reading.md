# 长视频阅读负担

状态：用户已授权实现；功能已完成，验证与交付记录见文末。更新：2026-09-27。

## 问题与目标

用户反馈：“长视频依旧需要看长文本，看起来很累。”

目标：降低长视频处理后的阅读负担，让用户通过“一句结论 + 一张结构图”快速抓住重点，点击节点后再看细节，无需通读全部章节摘要。

使用者与场景：使用 video-parallel 阅读长视频处理结果、希望先快速抓住结论的用户；不依赖特定视频题材或固定时长定义。

## 改动前的现状

- 已有全文概览和全文要点；随后所有章节的标题、摘要和要点一次性展开（`src/sidepanel.ts` 的 `renderSummary`、`createOverviewCard`）。
- 当前生成要求为全文概览 2–3 句话、3–5 条要点；每章摘要 2–3 句话、2–4 条要点，最多 16 章（`src/lib/summary.ts`）。这些是生成提示中的要求，不是严格的字数上限。
- 支持章节跳转、播放位置高亮及自动跟随；已有字号调整。
- 长字幕分批处理解决的是输入处理规模，不能据此认为阅读负担已经解决。

推断：默认展开的内容总量可能是负担来源；摘要重复、单条过长或用户更偏好非文字表达也可能影响体验，尚未获得用户确认。

## 已确认范围与决策

用户明确选择：

- “快速抓住结论：先看几条最重要的观点，需要时再展开”。
- “极简扫一眼：一句总判断加 3 个短句，合计约 100 字”。
- 随后探索图形表达，并选择“图为主：一句结论 + 一张结构图，点开节点再看细节”。该选择取代纯文字作为默认入口，极简阅读目标保留。

首版优先场景：

1. 默认展示一句结论和一张紧凑结构图；沿用极简预算，结论与图中标签的中文正文合计约 100 字，节点数量不随章节数量增长。不在图下重复铺开原有概览段落、全文要点和章节摘要。
2. 以约 3 个核心信息节点作为设计起点；只有表达关系确有必要时才增加连接标签或条件节点，不要求每章对应一个节点。首版最多三个节点；必要条件应保留在结论或短标签中，详细说明放入节点详情。
3. 详情默认收起，点击节点展开其说明和相关章节入口。章节正文按需展开；保留浏览全部章节的次级入口，用户可随时返回结构图。
4. 不把片段推荐或跟随播放阅读作为这次体验设计的主目标；保留现有跳转能力。

本次以结构图作为主入口，简短文字作为图中标签与必要的替代表达。音频、问答及装饰性配图暂不纳入首版。

## 图形表达方案

已确认图为默认主入口。图的作用是呈现信息之间的关系，不是把长段文字装进方框。

以下为围绕已选方向采用的产品默认，未预定图形生成或渲染技术：

按内容适配的形式：

| 内容关系 | 形式 | 表达重点 |
| --- | --- | --- |
| 结论、依据、限制条件 | 观点结构图 | 什么结论由什么支持，何时成立 |
| 步骤、先后或明确因果 | 流程图 | 如何推进，为什么产生结果 |
| 多个方案与共同维度 | 对比图 | 方案之间的关键差异 |
| 没有明确关系的独立要点 | 简洁卡片 | 不强造因果或层级 |

约束：在侧栏中可读，无需先放大或横向拖动才能理解主关系；默认只保留少量节点和短标签，详细说明按需展开；关系须有字幕依据；不能用未提供的数值编造统计图。没有明确因果时不能仅因时间先后画成因果箭头。

实现采用由模型生成的结构化图文数据与原生 HTML/CSS 呈现。文字始终是可访问的 DOM 内容，无需图片服务或新增图形库；失去图形样式时仍可读取结论、节点与详情。

## 可观察的验收标准

以下将已确认目标转为验收行为；展开布局等为本文采用的产品默认，后续可细化：

- 一段长视频生成了 16 章时，初始阅读内容仍为一句结论和一张紧凑结构图，结论与图中标签合计约 100 个中文字，章节正文不可默认铺开。预算不含视频标题和操作标签。
- 结论直接表达视频的核心判断或主旨；节点补充最重要的信息，避免重复结论或机械罗列章节名。对于没有明确结论的视频，概括主旨，不杜撰主张。
- 对含有明确步骤的视频，可从图中辨认推进顺序；对多个方案的讨论，可直接比较主要差异；独立观点不强行连成因果链。具体图形须服务于内容关系。
- 点击节点可查看对应说明和相关章节入口，再收起返回；展开操作本身不改变播放位置，显式点击时间戳才跳转。节点可以关联多个章节，不虚构精确到句的时间定位。
- 处于图形概览时，播放推进不会自动展开章节或把视图滚离结构图；详情中的播放跟随交互可在实现时细化。
- 压缩表达时保留影响结论的重要条件和不确定性；不能用字符串截断达成字数目标。字幕不足以支持三个核心节点时少列，不为凑数补写。
- 图形无法显示时仍可读取简短文字替代内容；生成失败时显示明确失败状态。如保留旧结果，应标明其来源状态，不以截断旧摘要冒充新结果。
- 使用实际长视频结果，在侧栏常见宽度检查可读性、长度、关系忠实性及节点展开操作；至少覆盖多章节、含关键条件的内容。再由用户判断是否能扫一眼抓住重点。自动化与示例交互已验证，实际内容和用户主观验收待补。

## 约束与开放问题

- 当前无阻塞产品方向的待答问题。
- 首版长度规则：中文、日文、韩文图中正文目标约 100 字，硬上限 140 个 Unicode 字符；其他语言目标约 60 词，上限 90 词及 650 个字符。超限会重试，仍不合规则显示失败，绝不裁切句子。
- 待补验证材料：实际验收视频及处理结果。当前代码阅读只能证明现有行为，不能证明新体验已降低疲劳。
- 范围默认：统一采用结论优先的入口，不新增长视频时长开关；本次先调整面板阅读体验，复制和 Markdown 导出保持完整内容。这些默认选择可随用户反馈修订。

## 实现与验证记录

- 图形类型为论证、步骤、对比或独立观点；节点包含短标签、关系、详细说明及一个或多个已返回章节的起始 ID。非法类型、长度、重复标签、无效引用均被拒绝。
- 图只在最终全片汇总时生成，分批中间结果仍保留完整摘要和关键条件。校验失败沿用最多一次重试，并提供错误反馈。
- 提示版本从 6 升至 7，缓存结构从 4 升至 5；保留旧缓存的明确标识与折叠阅读，新图必须通过校验后才能恢复。
- 节点采用原生按钮，支持回车键；章节采用原生折叠控件。节点详情和完整章节列表彼此独立，点击时间戳才跳转。
- Markdown 复制与导出保持完整概览和章节，不因首屏精简而丢失内容。
- 已在原生 Chrome 的 360px iframe 中验证示例首屏、鼠标及回车展开/收起、多章节引用、完整章节折叠、显式时间按钮。浏览器连接器报 request-header policy 错误，改用原生 Chrome 完成验证。
- 另在 320px 容器中验证流程、对比与独立观点布局，十六章保持折叠，三个容器均无横向溢出。
- `npm run package` 通过：锁文件依赖下类型检查、Biome、87 项测试、构建与打包全部通过。测试覆盖生成校验与重试、分批最终汇总、旧/新缓存、完整导出、节点展开与播放隔离。
- 实际长视频调用 Provider 后的关系忠实性、真实视频 seek 和用户疲劳改善尚未验收；示例交互及自动化测试不能代替这些证据。
- 本轮不发布版本或部署扩展；代码提交和推送结果由交付回执记录。
